# Спецификация «Календарь звонков»

Статус: черновик, ожидает утверждения. Источник решений: карта wayfinder (GitHub issue #2) и её закрытые тикеты. Глоссарий терминов: `CONTEXT.md`.

## 1. Назначение

Сервис онлайн-записи на звонок: гость выбирает тип события и свободный слот в календаре, оставляет имя и email; владелец календаря управляет типами событий и смотрит предстоящие встречи. Спецификация описывает целевое состояние приложения; текущая реализация в репо является референсом и заменяется.

## 2. Роли и доступ

- Две роли: Владелец календаря и Гость. Регистрации и авторизации нет.
- Владелец календаря: единственный заранее заданный профиль, все административные страницы работают от его имени без входа в систему.
- Гость: анонимный посетитель, записывается без создания аккаунта.
- Административный раздел (`/admin`) технически не защищён. Допущение осознанное: демонстрационный сервис без чувствительных данных.

## 3. Доменные правила

### Тип события

- Атрибуты: id, название, описание, длительность в минутах.
- Длительность: минимум 30 минут, кратна 30. Отдельного максимума нет: запись должна целиком помещаться в рабочий интервал дня.
- Владелец создаёт типы событий. Редактирование и удаление типов вне объёма MVP.

### Слот и сетка

- Сетка возможных начал слотов: каждые 30 минут в интервале 09:00-18:00 каждого дня по времени владельца календаря.
- Для типа события длительностью N старт доступен, если интервал [старт, старт + N) целиком лежит в 09:00-18:00 того же дня и не пересекается ни с одной существующей записью.
- Слоты не хранятся как предсозданные сущности: сервер вычисляет их на лету. Хранятся только типы событий и записи.

### Окно записи

- Окно: 14 календарных дней по времени владельца, включая текущий день.
- Прошедшие слоты недоступны, включая прошедшее время текущего дня.

### Занятость

- Запрещено любое пересечение интервалов записей, в том числе записей разных типов событий.

### Гонки и идемпотентность

- При одновременной записи двух гостей на пересекающиеся интервалы первый получает 201, второй 409 Conflict.
- POST создания записи идемпотентен по заголовку Idempotency-Key (UUID, генерируется клиентом на попытку записи): повтор с тем же ключом возвращает первичный результат и не создаёт дубль.

### Время и часовой пояс

- Сетка и окно вычисляются сервером в часовом поясе владельца; значение по умолчанию Europe/Moscow, задаётся в конфиге сервера.
- API передаёт время в UTC (ISO 8601, формат date-time).

### Запись

- Данные записи: тип события, время начала, имя гостя, email гостя. Больше ничего.
- Отмена и изменение записей вне объёма MVP.

## 4. Страницы и сценарии

### Гость

- `/`: каталог типов событий (название, описание, длительность). Пустой каталог: сообщение «Нет доступных типов событий».
- `/book/:eventTypeId`: календарь свободных слотов на окно записи (14 дней). Выбор слота открывает форму записи (имя, email) на той же странице, отправка создаёт запись. Нет свободных слотов: сообщение «Свободных слотов нет».
- После успешного создания: экран подтверждения с датой, временем и названием типа события.
- Ошибки формы: 409 (слот уже занят) — уведомление и обновление списка слотов; 400 — подсветка невалидных полей; 404 — «Тип события не найден».

### Владелец календаря

- `/admin/event-types`: список типов событий и создание нового (название, описание, длительность в минутах).
- `/admin/meetings`: предстоящие встречи всех типов событий: время, тип события, имя и email гостя. Сортировка по времени начала, прошедшие не показываются.

## 5. API

Канонический источник контракта: TypeSpec в `contracts/` (`main.tsp`). Артефакт `contracts/generated/openapi.json` (OpenAPI 3.0.0) генерируется командой `npm run generate` и коммитится в репо.

| Операция | Эндпоинт | Ответы |
|---|---|---|
| EventTypes_list | `GET /api/event-types` | 200 `EventType[]` |
| EventTypes_create | `POST /api/event-types` | 201 `EventType`, 400 |
| Slots_list | `GET /api/slots?eventTypeId=` | 200 `Slot[]`, 404 |
| Bookings_create | `POST /api/bookings` (заголовок Idempotency-Key) | 201 + Location + `Booking`, 400, 404, 409 |
| Meetings_list | `GET /api/meetings` | 200 `Meeting[]` |

- Ошибки: единый формат ProblemDetails (RFC 9457).
- Время: UTC, формат date-time. Слот отдаёт startUtc и endUtc.
- Каталог гостя и список типов владельца обслуживает один эндпоинт `GET /api/event-types`.

## 6. Генерация кода из контракта

### Контракт (`contracts/`)

- npm scripts: `generate`, `lint` (`tsp compile --no-emit --warn-as-error`, рулсет `@typespec/http/all`), `format:check`.
- CI: джоба `contracts` — `npm ci`, lint, format:check, generate, drift-check (`git diff --exit-code`).

### Фронтенд

- orval 8.40.0: генерация хуков TanStack Query v5 и типов из `contracts/generated/openapi.json`.
- Сгенерированный код коммитится; в CI drift-check после регенерации.
- Требование: Node >= 22.18 (локальную машину обновить; в CI Node 22).

### Бэкенд

- MinimalOpenAPI 1.1.0 (Roslyn source generator): из `contracts/generated/openapi.json` при компиляции генерируются контрактные records с DataAnnotations, маршруты, регистрация DI и базовые классы хендлеров. Нереализованная операция — ошибка компиляции MOA001.
- Сгенерированный код не коммитится (генерация при сборке). Generated-дереву нужен `NoWarn` CS1591 (нет XML-доков).
- Валидация запросов: собственный DataAnnotations-фильтр через генерируемый `EndpointConfigurationBase`: 400 + `application/problem+json` с ошибками по полям. Фильтр не рекурсирует во вложенные объекты; графы запросов плоские. Встроенный `AddValidation` не применяется: он не видит типы из чужого source generator.
- `MapOpenApi`, пакет `Microsoft.AspNetCore.OpenApi` и рантайм-эндпоинт `/openapi/v1.json` убираются: контракт живёт в `contracts/generated/openapi.json`. Пин `Microsoft.OpenApi` 2.7.5 перестаёт быть критичным.

## 7. Переход от текущей реализации

- Сущности `TimeSlot` с предсозданными почасовыми слотами и `DbSeeder` слотов убираются: слоты вычисляются, хранятся только типы событий и записи.
- Существующая dev-БД пересоздаётся (в ней только сидированные данные), `DbSeeder` переписывается под типы событий.
- Ручные fetch-обёртки и продублированные типы в `client/src/api/slots.ts` заменяются сгенерированным клиентом.
- Smoke-тесты бэкенда обновляются под новый контракт.

## 8. Нефункциональные требования

- Dev-запуск: `dotnet run --launch-profile http` (http://localhost:5262) + `npm run dev` из `client/` (http://localhost:5173), запросы через Vite-прокси `/api`, CORS не настраивается.
- Тесты: бэкенд — интеграционные xUnit + `WebApplicationFactory` с изолированной temp-SQLite на прогон; фронтенд — vitest + testing-library.
- CI: backend build (TreatWarningsAsErrors) -> format -> test; frontend lint -> build -> test; contracts (npm ci -> lint -> format:check -> generate -> drift-check); frontend codegen drift-check.

## 9. Вне объёма

- Авторизация и регистрация (осознанно отсутствуют).
- Отмена и изменение записей, редактирование и удаление типов событий.
- Настраиваемое расписание владельца (сетка и часы фиксированы).
- Email-уведомления, оплата, деплой.
- Раскладка спецификации на тикеты реализации: следующее усилие после утверждения.
